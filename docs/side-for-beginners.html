0먼저, Side가 무엇인가요?

"어제 그걸 어디서 봤더라?"를 다시 찾는 개인용 기록 도구입니다.

예를 들어 어제 브라우저에서 문서를 읽고, 메모 앱에 문장을 적고, 다른 앱에서 관련 화면을 살펴봤다고 해 봅시다. 며칠 뒤 정확한 제목이나 주소가 떠오르지 않아도 Side에 연결된 에이전트에게 그 일을 찾아 달라고 할 수 있습니다. Side는 현재 Mac에서 허용된 화면의 텍스트와 활동을 기록하고, 날짜별 요약과 출처를 만듭니다.

브라우저 안의 탭만이 아니라 Mac 앱의 활성 창도 대상입니다. 다만 "Mac의 모든 것을 빠짐없이 기억한다"는 뜻은 아닙니다. 권한이 있어야 읽을 수 있고, 제외한 앱·웹사이트와 비밀번호 필드는 관찰하지 않습니다. 접근성 텍스트가 없는 화면에는 선택적으로 화면 글자 인식이 쓰입니다.

먼저 알아둘 말
캡처(capture, 활동 기록)
지금 보고 있는 창의 제목, 주소, 읽을 수 있는 글, 입력이 끝난 문장 같은 단서를 Side가 모으는 일입니다. CCTV 영상처럼 화면을 계속 보관한다는 뜻은 아닙니다.
먼저 알아둘 말
요약(summary, 간추린 기록)
짧은 시간 동안 모인 단서를 보고 "무엇을 했는지"를 글로 정리한 것입니다. Side는 10분 단위 요약과 더 긴 묶음 요약을 만들고, 하루 페이지로 정리합니다.

1한 줄로 이해하기

개인 메모와 도서관 검색대를 함께 떠올리면 쉽습니다.

핵심 메시지

Side는 하루의 단서를 적고,
나중에 출처까지 찾아줍니다.

내가 직접 매번 메모하지 않아도, 허용된 앱에서 무엇을 보았는지 짧은 기록을 남깁니다. 에이전트가 질문을 받으면 그 기록이나 요약에서 관련 부분을 찾아 e: 또는 s:로 시작하는 출처 번호를 돌려줍니다. 브라우저 자체 방문 기록에서 찾은 결과에는 h:가 붙습니다.

비유하자면 메모를 써 주는 조수와 책 위치를 알려 주는 사서가 한 앱에 있는 셈입니다. 조수가 놓친 화면은 기록되지 않을 수 있고, 요약이 틀릴 수도 있으므로 중요한 사실은 출처를 다시 열어 확인해야 합니다.

2활동이 기억이 되는 과정

관찰 → 로컬 보관 → 요약 → 회상의 네 단계입니다.

Side가 보는 첫 지점은 현재 활성 창입니다. Accessibility(손쉬운 사용) 권한으로 읽을 수 있는 글과 창 정보를 가져오고, Input Monitoring(입력 모니터링)은 상호작용과 입력 문장 완성 신호를 돕습니다. 읽을 글이 없는 화면에 한해, 사용자가 허용했다면 OCR(Optical Character Recognition, 화면 글자 인식)으로 화면의 글자만 추출합니다. 이미지를 기록으로 남기지는 않습니다.

원본 기록은 Mac 안의 암호화된 ledger(원장, 시간순 장부)에 들어갑니다. Side는 알려진 비밀번호·토큰·카드 번호 패턴을 먼저 가리지만, 규칙으로 모든 민감한 값을 알아낼 수는 없습니다. 하루 요약 페이지와 검색 색인은 별도 파일로 만듭니다. 원본의 기본 보관 기간은 14일이고, 요약은 직접 지울 때까지 별도로 남습니다.

서랍과 색인 카드 비유

원본 기록은 잠긴 서랍 속 영수증과 비슷합니다. 요약은 "오늘 무슨 일을 했는지" 적은 일기이고, 검색 색인은 일기에서 원하는 부분을 빨리 찾기 위한 카드 목록입니다.

다만 실제 기록은 영수증보다 복잡합니다. 읽기 어려운 앱, 비공개 화면, 제외 규칙 때문에 빈칸이 생길 수 있습니다.

3키워드 검색인가요, 벡터 검색인가요?

질문에 따라 둘 다 사용합니다. 검색하는 대상이 다릅니다.

정확한 단서가 있을 때

history_search — 단어와 시간으로 찾기

앱 이름, 페이지 제목, 주소의 단어, 입력 문장처럼 실제 기록에 있는 표현을 찾습니다. 최근 활동에 가산점도 줍니다. "어제 오후 sqlite-vec 문서"처럼 시기와 키워드가 기억날 때 좋습니다. Side 캡처 e:, 요약 s:, 브라우저 방문 기록 h:를 찾으며 임베딩 벡터는 쓰지 않습니다. h:에는 방문 시각·제목·주소가 있고 화면 본문은 없습니다.

표현이 가물가물할 때

memory_search — 단어와 의미를 함께 찾기

날짜별 요약 페이지를 단어 검색과 embedding(임베딩, 문장의 뜻을 숫자로 옮긴 것)으로 함께 찾습니다. 예를 들어 기록에는 "화면 글자 인식"이라고 적혔는데 질문은 "OCR 문제"라고 해도 관련 내용을 찾을 가능성이 있습니다. 임베딩 계산은 Mac에 동봉된 MiniLM 모델이 로컬에서 합니다.

출처를 확인할 때

history_read — 번호를 열어 보기

검색 결과의 e: 또는 s: 번호를 그대로 넣어 원본 기록이나 요약을 읽습니다. h: 번호는 이 도구로 열 수 없고 검색 결과의 제목·주소만 볼 수 있습니다. 원본 보관 기간이 끝나면 그 원본은 열리지 않을 수 있지만 관련 요약을 찾을 수 있습니다.

벡터란?
vector search(벡터 검색, 뜻이 비슷한 글 찾기)
문장을 숫자 좌표로 바꾼 뒤 가까운 것을 찾습니다. 도서관에서 제목이 정확히 같지 않아도 주제가 비슷한 책을 추천받는 느낌입니다. Side에서는 요약된 하루 페이지에 이 방법을 쓰며, 모든 원본 이벤트를 벡터로 찾는 것은 아닙니다.

4에이전트에게 어떻게 물어보나요?

Side 도구를 먼저 연결하고, 찾는 단서와 확인 방법을 함께 말하면 됩니다.

Side는 MCP(Model Context Protocol, AI와 도구가 대화하는 약속) 서버를 제공합니다. Claude Code, Codex, Cursor, Grok Build, Aside 등 MCP 도구를 등록할 수 있는 클라이언트에서 Side 실행 파일을 연결하면 세 가지 검색 도구를 쓸 수 있습니다. 설치만으로 모든 에이전트에 자동 연결되는 것은 아닙니다. 각 클라이언트에 한 번씩 등록해야 합니다.

질문 예시 1 · 정확한 기록

시간과 단어가 기억나요

“어제 오후에 본 sqlite-vec 설치 문서를 Side의 history_search로 찾아줘. e:나 s: 출처가 있으면 history_read로 열어 핵심만 알려줘. h:만 있으면 제목과 주소를 보여줘.”

시간 범위를 알려 주면 엉뚱한 동명이인 문서를 줄이기 쉽습니다. 읽을 수 있는 출처를 열어 달라고 하면 요약만 보고 추측하는 일을 줄일 수 있습니다.

질문 예시 2 · 주제만 기억

정확한 표현이 기억나지 않아요

“지난주에 로컬 임베딩 성능을 조사한 활동을 Side의 memory_search로 찾아줘. 날짜와 관련 요약을 알려 주고, 확인 가능한 출처가 있으면 함께 보여줘.”

주제는 기억나지만 당시 문구가 떠오르지 않을 때 의미 검색을 먼저 시킵니다. 결과가 넓으면 날짜나 앱 이름을 추가해 다시 찾으면 됩니다.

Side 도구 등록 · 설치 후 한 번만
claude mcp add --scope user side -- "/Applications/Side.app/Contents/Resources/side" mcpClaude Code에 사용자 범위로 연결
codex mcp add side -- "/Applications/Side.app/Contents/Resources/side" mcpCodex에 연결
grok mcp add --scope user side -- "/Applications/Side.app/Contents/Resources/side" mcpGrok Build가 Side 기록을 검색하도록 연결
명령은 Side가 실행 중일 때 터미널에 복사해 붙여넣으면 됩니다. Grok Build 등록은 요약 모델 설정과 별개이며 실제 도구 호출은 아직 확인하지 않았습니다. Cursor와 Aside의 등록 화면은 저장소의 docs/agents.md에 적혀 있습니다.

5설치하고 설정하기

소스코드를 내 Mac에서 빌드해 Applications 폴더에 넣습니다.

Side는 현재 소스코드 배포용이며 내려받아 바로 여는 사전 빌드 앱은 제공하지 않습니다. GitHub에서 소스코드를 받은 뒤 저장소 폴더의 터미널에서 아래 순서로 실행합니다. macOS 14 이상, Bun, Xcode Command Line Tools, FTS5와 확장 로딩을 지원하는 SQLite dylib가 필요합니다. 빌드 스크립트는 Homebrew의 SQLite를 찾고, 다른 위치의 파일은 SIDE_SQLITE_LIBRARY로 지정할 수 있습니다. 빌드할 때 MiniLM 모델도 앱에 넣으므로 처음에는 인터넷이 필요할 수 있습니다.

로컬 빌드 · 순서대로 복사
bun install --frozen-lockfile필요한 코드 패키지 설치
bun run buildMac 앱 만들기
ditto apps/side-mac/.build/release/Side.app /Applications/Side.app앱을 Applications에 복사
open /Applications/Side.app메뉴바 앱 시작
한 줄씩 그대로 복사하세요. 이미 Side를 실행 중이면 새 앱을 복사하기 전에 먼저 종료합니다.

처음 시작하면 손쉬운 사용과 입력 모니터링 권한을 순서대로 안내합니다. 화면 기록은 OCR을 쓸 때 필요하며 건너뛸 수 있습니다. 요약 제공자를 설정하고 싶다면 API 키를 Keychain에 저장하거나, Mac에 Claude Code를 설치하고 로그인해 둔 경우 그 기존 로그인 옵션을 선택할 수 있습니다. 제공자를 등록한 뒤에도 설정에서 “이 제공자에게 증거 전송”을 켜야 실제 활동으로 요약을 만듭니다.

이 Mac의 현재 설정은 MiMo 2.6 Pro를 먼저 시도하고 MiniMax M3를 다음 제공자로 둡니다. 이는 사용자가 선택한 순서이며 모든 Side 설치의 기본값은 아닙니다. MiMo는 도구 호출을 강제로 고정할 수 없어서, 제공자 연결이 정상이더라도 개별 요약은 모델의 응답 오류나 형식 위반으로 실패할 수 있습니다. 기록 화면이 비어 있다면 10분 창이 아직 끝나지 않았는지와 요약 상태를 확인해 보세요.

앱을 다시 빌드했다면
macOS 권한이 예전 앱을 가리킬 수 있습니다

로컬 앱은 임시 서명으로 빌드됩니다. 새 빌드로 교체한 뒤 Side가 권한을 못 읽는다면 시스템 설정 → 개인정보 보호 및 보안에서 이전 Side 항목을 제거하고 /Applications/Side.app을 다시 추가합니다. 같은 권한 스위치를 반복해서 누르기 전에 앱 경로를 확인하세요.

진단 방법
설치 상태를 한 번에 확인

터미널에서 "/Applications/Side.app/Contents/Resources/side" doctor를 실행하면 Keychain, 권한, SQLite, 벡터 검색 모듈, 모델 캐시, 제공자 연결의 상태를 확인합니다. 제공자 연결 검사에는 실제 활동 대신 합성 문장을 사용합니다.

6보관·삭제·프라이버시

기억할 범위와 기간은 사용자가 조절합니다.

메뉴바에서 15분, 30분, 1시간 또는 직접 재개할 때까지 캡처를 일시정지할 수 있습니다. 설정의 제외 목록에는 관찰하지 않을 앱이나 웹사이트를 넣습니다. 원본 캡처의 보관 기간은 1·3·7·14·30일 중 고를 수 있고 기본값은 14일입니다. 설정에서 최근 10분, 지난 1시간, 오늘 또는 전체 기록을 삭제할 수 있습니다.

Side의 원본 데이터는 이 Mac의 ~/Library/Application Support/Side/에 있습니다. 알려진 민감 패턴을 저장 전에 가리고 원본 기록의 민감 컬럼은 암호화하지만, 규칙으로 모든 비밀을 찾아내지는 못합니다. 요약과 날짜별 페이지는 로컬 파일에 읽을 수 있는 글로 남습니다. 전체 삭제는 Side 원본·요약·색인을 지우고 암호화 키를 교체합니다. 브라우저 자체 방문 기록은 그대로이며 모델 API 키도 Mac의 Keychain에 별도로 남습니다.

외부 모델을 연결할 때
전송 허용 범위를 먼저 확인하세요

“이 제공자에게 증거 전송”을 켜면 가려진 10분 활동 브리핑과 6시간 묶음 브리핑이 표시된 모델 제공자 주소로 전송됩니다. Side에 연결한 에이전트도 검색 결과를 자신의 모델에 전달할 수 있습니다. 각 서비스의 저장 정책까지 Side가 대신 통제하지는 못합니다.

내가 통제할 수 있는 것
멈추고, 빼고, 지우기

잠깐 쉬고 싶으면 메뉴바에서 일시정지하고, 특정 장소를 계속 제외하려면 앱·웹사이트 제외 목록을 사용합니다. 이미 만들어진 Side 기록을 없애려면 설정의 기록 삭제를 사용하세요. 상황 인식 기능을 끄는 것만으로 과거 기록이 즉시 삭제되지는 않으며, 브라우저 방문 기록을 지우려면 브라우저에서도 따로 삭제해야 합니다.

처음 사용한다면

짧은 활동 하나로 흐름을 확인해 보세요
